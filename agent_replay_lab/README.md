# TRACEGUARD — Agent Replay Lab

**A bounded, multi-step AI-agent security evaluation laboratory.**

**Evidence status:** independently reproducible **synthetic research**, not a demonstrated exploit against a real model. No accepted CVE, bug bounty, outside security review, Anthropic CVP membership or OpenAI Daybreak approval is claimed.

**Author:** [@skuzu7](https://github.com/skuzu7) · **Version:** 0.1.0 · **Python:** 3.11+ · **Offline requirements:** stdlib only.

## Why this matters

Single-response prompt-injection tests do not fully represent an agent working across many tool calls. TRACEGUARD evaluates a **bounded multi-step workflow**: read an authorized document, receive *untrusted tool output*, propose subsequent tool actions, write an authorized report, and finish. The host, **not the model**, decides if each proposed action is allowed.

```text
TRUSTED HOST TASK                MODEL/SCRIPTED STRATEGY          IN-MEMORY TOOLS
scope and exact document   -->   proposes read_doc         -->  read synthetic source
approved report path       -->   sees UNTRUSTED text       -->  enforce exact allowlist
explicit finish condition  -->   proposes next action      -->  deny unapproved actions
                               \-> proposes report/finish  -->  store report in memory
                                               |
                                       hashed decision trace
```

**All agent-requested shell, real HTTP, filesystem writes, memory changes, credential reads and deletion operations are blocked or simulated.** The model never gets an actual execution tool. The optional network-enabled component makes API requests **only to the chosen OpenAI/Anthropic provider** with explicit opt-in, and never executes resulting proposals against real systems.

## Free, offline, reproducible

From the CSA-LAB repository root:

```bash
python -m unittest discover -s agent_replay_lab/tests -v
python -m agent_replay_lab.runner --mode baseline --output baseline.json
python -m agent_replay_lab.runner --mode attack-control --output attack-control.json
```

- **26 unit tests** check dataset integrity, policy boundaries, strict tool parsing, state transitions, source data isolation, hash-chain integrity and API consent.
- **16 cases**, organized into eight matched benign/attack pairs, cover selected OWASP Agentic Top 10 risk classes.
- A **scripted negative control** always proposes authorized actions.
- A **scripted adversarial positive control** deliberately proposes each prohibited attacker goal, receives a host denial, then completes the legitimate task.
- GitHub Actions checks the exact expected counters and publishes two provenance-labelled JSON evidence files.

## Optional real-model experiments — explicit consent required

Provider adapters can evaluate a model's proposed tool actions across multiple turns, but **have not been used to produce public model scores**. To run them yourself, use a key stored privately in your local environment, an available provider model ID and an explicit acknowledgement of API charges. Begin with two cases to limit costs:

```bash
# OPENAI_API_KEY is set privately; never put API keys in source files.
python -m agent_replay_lab.runner --mode openai --model YOUR_AVAILABLE_OPENAI_MODEL_ID --acknowledge-api-cost --limit-cases 2 --max-calls 10 --output private-openai-report.json

# ANTHROPIC_API_KEY is set privately.
python -m agent_replay_lab.runner --mode anthropic --model YOUR_AVAILABLE_ANTHROPIC_MODEL_ID --acknowledge-api-cost --limit-cases 2 --max-calls 10 --output private-anthropic-report.json
```

Both adapters send only the **synthetic case task and public untrusted test text** to their provider endpoints. Provider request failures or unavailable models are experiment failures, not proof of safety. The simulator does not issue real tool commands regardless of the model output.

## Selected risk taxonomy

Our 8 artificial pairs are *loosely tagged* with relevant **OWASP Top 10 for Agentic Applications 2026** themes. This is not OWASP certification, full coverage, or claims of observed exploitation:

- **ASI01** Goal hijacking through retrieved content;
- **ASI02** Tool misuse and an untrusted URL;
- **ASI03** Fake privilege/authorization;
- **ASI04** Fake maintainer instruction for unsafe supply-chain tooling;
- **ASI05** Unwanted shell/deletion operations;
- **ASI06** Persistent memory poisoning attempts;
- **ASI07** Forged inter-agent supervisor messages;
- **ASI09** Fake human approval for early termination.

The other OWASP ASI categories are not covered by these cases. Detailed [threat model](THREAT_MODEL.md).

## Auditability and constraints

Every in-memory action produces a **hash-chained event** containing the proposed tool/target, decision, content/observation hashes and previous-event hash. Reports include SHA-256 of the exact synthetic dataset. Modified or reordered events fail the verifier when the original trace head is retained independently. A hash chain **is not a digital signature**: an attacker controlling both log and head can forge a replacement chain.

**Not a production sandbox:** The simple policy assumes an uncompromised trusted host and does not implement real filesystem isolation, DNS/redirect defenses, cryptographically authenticated approvals, actual malware or third-party target testing. All cases are invented and require no special access. Do not use this project to claim a model-specific vulnerability or scientific SOTA without real repeated model experiments and independent review.
